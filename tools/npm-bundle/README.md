# npm Bundled Dependency Fixes

npm 12.2.2 still ships older bundled libraries independently of the application's dependencies. This directory locks reviewed repairs and updates for that build toolchain. It is monitored by Dependabot and audited at all severity levels in CI; neither the npm version nor application-only audit covers the whole installed build toolchain.

Install with `npm ci --prefix tools/npm-bundle --install-strategy=nested --ignore-scripts`. The nested strategy preserves each replacement's dependency closure without changing unrelated npm libraries. Run apply.mjs with the absolute installed npm package directory, for example `node tools/npm-bundle/apply.mjs "$(npm root -g)/npm"` on a controlled build/CI installation.

The helper validates the destination, never downgrades a newer version, and normally requires the same major API. It updates node-gyp to 13.1.0 first (within npm's declared range), then installs Undici 8 only when that parent's dependency range accepts it. The explicit npm 12.2.2 adaptation replaces glob 13 with 14.0.6 and minimatch 10 with 11.0.8, addressing GHSA-3g3m-2fjr-6pw4 and GHSA-g3hv-75wg-m249. These two changes exceed npm's upstream ranges: they are locally reviewed adaptations, not vendor updates. Exact npm/from/to guards prevent this permission from extending to future unreviewed versions or other libraries.

Run `node tools/npm-bundle/verify.mjs "$(npm root -g)/npm"` after applying repairs. The suite resolves the actual installed modules and checks identities, glob/minimatch APIs, pre-aborted traversal, workspace installation, clean lockfile installation, dependency listing and package file inclusion/exclusion. Docker and CI run it before installing application dependencies, and separately compile/load a native addon through the repaired node-gyp with a real Node-header download. Recheck and retire repairs when upstream npm ships them. Do not change your shared system npm installation without reviewing its other consumers.

The isolated repair bundle has its own accurate audited lockfile. npm's original bundled lock metadata is not rewritten to pretend its vendor ranges accept these adaptations; use actual-file inventory/scans for the installed repaired CLI. No force/legacy-peer-deps, scanner exception or false component version is used.

These files are used in the Docker build stage and CI, not included in the final scratch runtime. Scans of those surfaces must be reported separately. A package manager's latest version does not prove that its bundled dependencies are current or free of known vulnerabilities.
